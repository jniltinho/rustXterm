# Protocol test lab

Disposable Docker Compose lab for rustXterm integration tests (design D11). Every published port binds
`127.0.0.1` only. All credentials below are fictional lab material; never point tests at real servers.

## Run

```sh
lab/lab.sh up      # build images, generate lab/.generated/, start and wait for healthchecks
lab/lab.sh status  # docker compose ps
lab/lab.sh test    # cargo xtask lab test in the toolchain container (host network)
lab/lab.sh down    # stop and remove containers and volumes
```

`lab test` runs `cargo test --workspace --tests -- --ignored` (lab tests are `#[ignore]`d) with
`CARGO_TARGET_DIR=target/lab`, and fails on any test failure or unless the executed test names equal
`lab/expected-tests.txt` exactly (blank lines and `#` comments ignored). Add a test name there whenever a lab
test is added or renamed.

## Services

| Service | Host port | Notes |
|---|---|---|
| `sshd` | 2222 | OpenSSH, `LogLevel DEBUG1`, `AcceptEnv FOO`, X11 forwarding (`xauth`, `xeyes`, `xdpyinfo`), compression, TCP forwarding |
| `bastion` | 2223 | Same image as `sshd`; also on the `internal` network |
| `internal` | none | Same image; reachable only as `internal:22` through `bastion` |
| `ftp` | 2121, passive 30000-30009 | vsftpd, plain FTP and explicit FTPS (`AUTH TLS`), self-signed cert built into the image |
| `ftps-implicit` | 2990, passive 30010-30019 | vsftpd, implicit FTPS, TLS required |
| `rdp` | 13389 | xrdp + xorgxrdp, xterm session |
| `vnc` | 5901 | TigerVNC, VncAuth, xterm on `:1` |
| `telnetd` | 2323 | inetutils telnetd under inetutils-inetd (`login`, NAWS, TTYPE) |
| `echo` | 2007 | Raw TCP echo (`socat ... EXEC:cat`), same image as `telnetd` |

Host keys are generated fresh each time a container is created, so tests must not pin them across runs.

## Test environment

`cargo xtask lab test` sets for the test processes:

- `RXT_LAB_SSH_KEY`: absolute path of bob's private key (`lab/.generated/bob_ed25519`, generated by `lab.sh up`).
- `RXT_LAB_LOG_DIR`: directory with sshd logs, one file per host (`sshd.log`, `bastion.log`, `internal.log`),
  e.g. to check `keepalive@openssh.com` requests.

`lab/.generated/` is git-ignored and recreated on demand.

## Agent control: other-UID check

`lab/agent/uid-test.sh` (host side, Docker only) builds `apps/rustxterm/examples/agent_uid_probe.rs`, serves the
control socket as your UID in one container and connects as UID 12345 from another; it asserts the socket is
unreachable with default modes and, with modes loosened by hand, closed without a response (SO_PEERCRED). It is
not part of `lab test`.

## Vagrant (optional, never in CI)

For cases containers cannot cover: `lab/vagrant/debian/` (minimal Debian with sshd, alice on 127.0.0.1:2322) and
`lab/vagrant/windows/` (Windows Server evaluation box for RDP with NLA, 127.0.0.1:53389). Run `vagrant up` inside
the directory; the Windows evaluation license terms are the user's to accept. All test VMs (including the desktop
matrix) are created on demand and destroyed afterwards; see
[`vagrant/README.md`](vagrant/README.md) for how to rebuild each one.
