# M4 gate receipt: agent control integration (task 9.1)

Date: 2026-10-13. Spec: `agent-control` (CLI, local control channel, MCP server, permission
matrix, single authorization boundary, policies/approvals, no secret disclosure, audit).

## Setup

The GUI needs a display, so the integration tests start the engine headless in the test process
with the same wiring as `apps/rustxterm/src/main.rs`: the encrypted store (`rxt_ui::Vault`) as
`Records`, the real `rxt_platform_linux::UnixControl` in a temporary `$XDG_RUNTIME_DIR`, agent
control enabled with `set_agent_control(true)`. The real `rustxterm` binary
(`CARGO_BIN_EXE_rustxterm`) is the CLI and `rustxterm mcp` (child process, JSON-RPC over stdio).
The test thread plays the GUI: it accepts unknown lab host keys once (`Command::Answer`), cancels
secret prompts and answers approvals with `Command::AnswerApproval`. Lab server: Docker `sshd` on
127.0.0.1:2222, fictional `alice` account, saved password in the store.

## Notes

- No product bug was found by this batch; no product code changed.
- A disabled instance and no instance look the same to a client (no socket in both cases), so live
  commands exit 5 with a message naming both causes; exit 6 (`agent_control_off`) is reserved for a
  server that answers with that code.
- An agent cannot present or alter an approval: the approval is bound server-side to the hash of the
  exact request, so "changed parameters" over the channel is always a new request needing a new
  approval. The mismatch path itself is proven by the unit test named above.
