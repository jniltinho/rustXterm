Date: 2026-10-13. Spec: `terminal-emulation` scenarios "Output flood" and "Resize propagation".

## Machine

| Item | Value |
|---|---|
| CPU | AMD Ryzen 9 9900X 12-Core (24 threads), x86_64 |
| CPUs used | 4 (`docker run --cpus=4`, CFS quota via `RXT_DOCKER_CPUS=4`; not pinned cores) |

## Commands

```sh
lab/lab.sh up
RXT_DOCKER_CPUS=4 RXT_DOCKER_NET=host CARGO_TARGET_DIR=target/lab scripts/cargo-docker.sh sh -c \
  'cargo test --release -p rxt-ssh --test lab_gates -- --ignored --nocapture;
   cargo test --release -p rxt-ui --lib lab_gates -- --ignored --nocapture'
lab/lab.sh test   # 27 lab tests, matches lab/expected-tests.txt (debug build)
lab/lab.sh down
```

Tests: `crates/ssh/tests/lab_gates.rs` (`ssh_gate_flood_input_echo_resize_one_connection`) and
`crates/ui/src/lab_gates.rs` (`lab_gates::ui_gate_flood_tab_switch_echo_memory_resize`). Both run the
producer `yes "$(head -c 200 /dev/urandom | base64 -w0)"` for 30 s and print `GATE` lines.

Memory (UI test, `VmRSS` of the test process): idle with both tabs connected and empty scrollback 161,492 KiB;

Debug build (`lab/lab.sh test`, same 4-CPU limit): tab switch p95 67.31 ms, sibling echo p95 112.26 ms
(fails 100 ms: ~50 ms per frame to feed 1 MiB into the unoptimized terminal), resize to `stty` p95
113.91 ms, RSS growth 58,992 KiB. The UI test therefore asserts frame latencies only on optimized
builds and reports them in debug; memory and resize are asserted in both.

## Fix found by the measurement

The first run starved the background tab: the visible flooding tab was drained first and used the whole
1 MiB per-frame budget, so the sibling tab's echo never arrived (10 s timeout). `App::drain_output`
(`crates/ui/src/app.rs`) now reserves half the budget for background tabs (split evenly) and gives the
visible tab the rest; unit test `tests::flooding_visible_tab_does_not_starve_background_tab`.

## Deviations

- Spec says "two channels, one connection". The SSH-level test does exactly that (two shells on one
  `rxt_ssh::Client`). The engine opens one connection per tab, so the UI test uses two tabs = two connections.
- "Key event to bytes written to the transport" is measured at `ShellWriter::write` returning (hand-off to
  the russh session task), without instrumenting the engine; the end-to-end sibling echo bounds the full path.
  Likewise `window-change` is measured at `ShellWriter::resize` returning; the sub-millisecond remote
  `stty size` result bounds the time to the wire.
- Tab switch is timed in the egui_kittest harness (programmatic `SelectTab`, then `step()` + `render()`
  with lavapipe and image readback), not a real window with vsync; frames between samples were built
  without rendering.
- Reference machine is "x86_64, 4 cores, integrated GPU": here 4 CPUs of quota on a 12-core desktop CPU
  and software rendering; the lab server shares the host.
